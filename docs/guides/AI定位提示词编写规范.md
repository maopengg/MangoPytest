# AI 定位提示词编写规范

元素表的 3 组 `AI定位提示词` 列是 AI 元素定位的**唯一语义输入**。本文档给出写法、
正反例与体检规则。所有规则都由 `mangoautomation` 的解析代码实测得出，不是经验之谈。

---

## 1. 三列 = 同一段描述的三行

| 列 | 语义 | 必填 |
|---|---|---|
| `AI定位提示词1` | 控件描述：控件种类 + 区分特征 | **是** |
| `AI定位提示词2` | 所在区域 / 上下文 | 否 |
| `AI定位提示词3` | 排除项：必须以 `排除项：` 开头 | 否 |

运行时会按列序用**换行**合并，写入 `ElementModel.elements[0].prompt`。

> 为什么必须合并：库侧 `first_prompt()` 只读取 `elements` 中第一个非空 `prompt`
> （`element_healing/context/sanitizer.py`），逐 slot 分开填会让第 2、3 列对 AI 完全失效。

**为什么必须用换行**：库侧 `positive_prompt()` 用 `^\s*排除项\s*[：:]` 做**行首**匹配来剔除
排除条件。用 `|` 等分隔符把三列拼成一行时，排除项不再位于行首，**不会被剔除，反而会变成
必须命中的正向目标文本**——语义完全反转。

---

## 2. 六条规则

| # | 规则 | 依据 |
|---|---|---|
| R1 | **`排除项：` 必须独占一行且在行首** | `positive_prompt()` 行首匹配；写在句中会语义反转 |
| R2 | **用中文引号 `「」`／`“”` 包裹页面上真实存在的可见文案** | `_quoted_texts()` 会把它抽成最强目标文本 |
| R3 | **把关键点放在「的」之后，并以「的 + 控件种类」结尾** | `semantic_core_text()` 取最后一个「的」之后的片段作为核心必需文本 |
| R4 | 不要把 `| - _ / ： >` 和空格当装饰分隔符 | `split_target_text()` / `semantic_required_texts()` 会按它们切词，末段成为必需文本 |
| R5 | 不要把"排除项"写进描述句 | 同 R1 |
| R6 | 多行是官方支持的，用 `Alt+Enter` 输入 | `positive_prompt()` 按行 `splitlines()` 处理 |

### 推荐句式

```text
位于<区域>、显示「<可见文案>」的<控件种类>
位于<区域>的<控件种类>
```

以「的 + 控件种类」结尾，能让核心必需文本恰好等于控件种类，既不误伤也不遗漏。

## 3. 正例与反例

以 `ui-file-input`（文件上传输入框）为例：

| 写法 | 解析出的必需文本 | 判定 |
|---|---|---|
| `查找元素：ui-file-input` | `['input', …]`（连字符切词后的残渣） | ❌ 模板串，无增量语义 |
| `位于组件演示页的文件与下载区的文件上传输入框` | 含控件种类 | ✅ |
| `位于组件演示页的文件与下载区的文件上传输入框` + 另起一行 `排除项：下载按钮` | 排除项被正确剔除 | ✅ |
| `位于组件演示页的选择框，排除项：下载按钮` | `['下载按钮']` | ❌ **排除项反转成必需文本** |
| `文件上传\|选择文件\|排除项：下载` | `['下载按钮']` | ❌ **同样反转** |

其它示例：

| 元素 | 推荐写法 |
|---|---|
| `nav-components` | `位于顶部导航栏、用于切换到「Web UI 组件演示」的按钮` |
| `create-order` | `位于 HTTP API 靶场的订单业务区、显示「创建订单」的按钮` |
| `toast` | `位于页面右下角的浮动提示文本` |
| `demo-modal` | `位于确认弹窗的模态弹窗` |

## 4. 运行时变量

提示词支持 mangotools 的 `${{变量}}` 语法（`SyncElement.init_element()` 会对 prompt
执行 `test_data.replace()`），可以写参数化描述，例如
`位于订单表单、显示「${{idem_key}}」的文本输入框`。

⚠️ **变量未注入时 `replace_str` 会抛 `MangoToolsError`，元素初始化直接失败——与 AI 开关无关。**
因此体检会把未声明的变量报为**错误级**。只有在确认运行期一定注入时才使用变量。

---

## 5. 体检

```bash
python main.py --check-elements            # 全量产品
python main.py --check-elements --element-product mock_ui --max-issues 100
```

存在错误级结论时进程返回非 0，可直接接入提交前检查或 CI。

| 级别 | 规则 | 说明 |
|---|---|---|
| **错误** | `exclusion_not_at_line_start` | 排除项未独占行首（语义反转） |
| **错误** | `exclusion_only` | 只填了排除项、没有正向描述 |
| **错误** | `undefined_prompt_variable` | 使用了未声明的 `${{变量}}`（硬失败） |
| 警告 | `template_prompt` | 仍是 `查找元素：<元素名>` 模板串 |
| 警告 | `prompt_equals_element_name` | 去掉模板前缀后与元素名完全相同 |
| 警告 | `prompt_too_short` / `prompt_too_long` | 正向描述 < 6 或 > 120 字符 |
| 警告 | `missing_control_keyword` | **交互类**元素未含可识别的控件种类/作用域关键词 |
| 警告 | `missing_prompt` | 有固定定位器但完全没有提示词 |

加载元素表时也会体检：**错误级 fail fast**（避免语义相反的描述流入测试），警告级只记日志。

> `missing_control_keyword` 只对交互类元素生效（按元素名里的交互信号近似判断），
> 对 `history-result`、`demo-table` 这类纯展示元素不产生告警——库侧
> `target_intent` 的控件种类约束对展示元素没有意义。

### 可识别的关键词

库侧会从描述里解析「控件种类 + 作用域」并据此拒绝种类不符的候选，因此**显式写出**这些词能提高命中率：

- 控件种类：文件上传、上传控件、选择文件、单选框、单选按钮、复选框、勾选框、多选框、
  开关、下拉框、下拉选择框、选择框、组合框、搜索输入框、文本输入框、输入框、文本框、
  编辑区、按钮、链接
- 作用域：卡片、表格行、列表行、行记录、列表项、弹窗、对话框、抽屉、半屏窗口、表单

---

## 6. 维护建议

1. 新增元素时**同时**填写 `AI定位提示词1`；只填元素名等价内容等于没填。
2. 优先复用同一产品工作簿，不要按测试模式复制元素数据。
3. 改动元素表后执行一次 `--check-elements`，保证错误级为 0。
4. 提示词也是 `element_version` 指纹的一部分：**改提示词会让此前基于旧描述产生的自愈记录失效**，
   这是预期行为。
5. 工作簿自带的 `说明` worksheet 里也放了一份简要规范，便于在编辑 Excel 时直接查看。
