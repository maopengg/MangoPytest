# Mango Pytest 项目架构

## 全局结构

```text
mango_pytest/
├── auto_tests/
│   ├── common/mango_mock/    # Mango Mock 产品公共实现
│   ├── api/                  # simple、BDD、纯 pytest API Demo
│   ├── ui/                   # simple、BDD、纯 pytest UI Demo
│   ├── other/sql/            # 未完成，注册表禁用
│   └── project_registry.py   # 项目和环境唯一注册表
├── core/                     # 与具体产品无关的框架能力
├── tests/                    # Core、执行器和 Web 控制台测试
├── web_console/              # 本地执行与结构化报告页面
├── docs/
├── local_packages/           # 内部 wheel
└── artifacts/                # 全部运行产物，Git 忽略
```

## 职责边界

- `core/api|ui|sources|dal|execution` 只提供通用框架能力。
- `auto_tests/common/mango_mock` 存放同一被测产品跨 Demo 共享的协议客户端、Repository、Page Object、Flow 和能力执行器。
- 每个 Demo 保留自己的测试表达、Fixture 装配、数据工厂和配置。
- 根 pytest 只收集 `tests/`；Demo 由 `main.py` 在各自 rootdir 中隔离执行。
- 可执行环境只来自 `project_registry.py`，配置文件名不会自动变成可选环境。

## 六个 Demo

| 项目 | 定位 |
|---|---|
| `simple_api` | 少量基础 HTTP Case |
| `bdd_api` | 中文 Gherkin、大项目业务分层、多协议 |
| `pytest_api` | 纯 pytest、大项目 Service/Repository、多协议 |
| `simple_ui` | UI 操作能力入门与元素矩阵 |
| `bdd_ui` | 中文 Gherkin UI 业务与能力场景 |
| `pytest_ui` | 纯 pytest UI 业务与能力场景 |

运行命令和当前用例数量以仓库根 `README.md` 为准。
